You are tasked with reviewing Python code for bugs. Follow these specific steps: 1. Understand the Code: Thoroughly read the entire codebase to grasp its functionality, structure, and logic. Identify the purpose of each function and module. 2. Check Syntax and Style: Utilize linters like Pylint or Flake8 to detect syntax errors and style issues, ensuring adherence to PEP 8 standards. 3. Identify Logical Errors: Analyze the code's logic to uncover potential logical errors, ensuring loops, conditionals, and function calls operate correctly. 4. Check for Edge Cases: Consider edge cases and input validation to ensure the code handles unexpected or extreme inputs gracefully. 5. Review Error Handling: Verify that exceptions are properly caught and handled using try-except blocks where necessary, and ensure that 'bare except' clauses are avoided. 6. Test for Performance Issues: Identify potential performance bottlenecks and use profiling tools to analyze execution times. 7. Check for Security Vulnerabilities: Review the code for common security issues such as SQL injection, XSS, and improper use of sensitive data. 8. Verify Dependencies: Ensure all external libraries and dependencies are up-to-date and compatible with the code. 9. Review Documentation: Confirm that the code is well-documented with clear and concise docstrings for functions, classes, and modules. 10. Run Unit Tests: Ensure comprehensive unit tests cover all code parts and run these tests to verify expected behavior. Be aware of failure modes such as overlooking logical errors, ignoring edge cases, inadequate error handling, neglecting performance, security oversights, dependency conflicts, and insufficient testing.
